# Третья лабораторная работа по ПАТД

## Общее описание

Проект представляет собой реализацию **сегментированного дека (`SegmentedDeque<T>`)** на C++ и построенного на его основе **стека (`Stack<T>`)**.

Сегментированный дек хранит элементы не в одном непрерывном массиве, а в **двусвязном списке сегментов** фиксированной ёмкости. Каждый сегмент — это буфер на динамическом массиве с указателями начала и конца, что даёт амортизированное **O(1)** добавление и удаление с **обоих концов** и при этом доступ по индексу за O(числа сегментов). `SegmentedDeque<T>` реализует общий интерфейс `Sequence<T>`, поэтому к нему применимы те же операции, что и к прочим коллекциям проекта.

`Stack<T>` — это тонкая надстройка (LIFO) над `SegmentedDeque<T>`: `Push`/`Pop`/`Peek` сводятся к операциям с «хвостом» дека.

Контейнеры шаблонные и работают с любым типом, включая модели предметной области — **`Student`** и **`Teacher`**. Программа предоставляет интерактивное меню командной строки для построения дека над разными типами элементов и выполнения операций над ним.

## Функциональность

### Операции `SegmentedDeque<T>`

| Операция | Описание |
|----------|----------|
| **Append (push back)** | Добавление элемента в конец (амортизированно O(1)) |
| **Prepend (push front)** | Добавление элемента в начало (амортизированно O(1)) |
| **PopFirst (pop front)** | Извлечение элемента с начала |
| **PopLast (pop back)** | Извлечение элемента с конца |
| **Get / GetFirst / GetLast** | Доступ по индексу и к крайним элементам |
| **InsertAt** | Вставка элемента по индексу |
| **GetSubsequence** | Подпоследовательность `[start, end]` |
| **Concat** | Конкатенация с другим деком/последовательностью |
| **FindSubsequence** | Поиск вхождения подпоследовательности (наивный, по развёрнутому в массив содержимому) |
| **GetLength / IsEmpty** | Число элементов / проверка на пустоту |
| **GetEnumerator** | Перечислитель, обходящий все сегменты по порядку |

### Операции `Stack<T>`

| Операция | Описание |
|----------|----------|
| **Push** | Положить элемент на вершину (`storage_.Append`) |
| **Pop** | Снять элемент с вершины (`storage_.PopLast`) |
| **Peek** | Посмотреть вершину без снятия |
| **Get** | Доступ по индексу |
| **GetLength / IsEmpty** | Размер / проверка на пустоту |
| **Clear** | Очистка стека |
| **Concat** | Конкатенация двух стеков |

## Ключевые понятия

### Сегмент

Внутренний класс `SegmentedDeque<T>::Segment` — это буфер фиксированной ёмкости на `DynamicArray<T>` с тремя полями:

| Поле | Назначение |
|------|------------|
| `head_` | Индекс первого занятого элемента в буфере |
| `tail_` | Индекс последнего занятого элемента в буфере |
| `isEmpty_` | Флаг пустоты сегмента |

Число элементов в непустом сегменте равно `tail_ - head_ + 1`; флаг `isEmpty_` нужен, чтобы отличить **пустой** сегмент (`head_ == tail_`, элементов нет) от сегмента **с одним элементом** (`head_ == tail_`, элемент один) — по одним индексам они неотличимы. Добавление к концам сдвигает `tail_`/`head_` внутри буфера, что и обеспечивает O(1) на концах без перевыделений.

### Список сегментов

Сами сегменты хранятся в `DoublyLinkedList<Segment>`. Когда крайний сегмент заполняется, заводится новый и подшивается в начало/конец списка; когда сегмент пустеет после `Pop`, он удаляется из списка. Минимальная длина сегмента — **2** (проверяется в конструкторе).

### Модели предметной области

`Student` и `Teacher` имеют одинаковую структуру: имя, фамилия, отчество, числовой `id` и дата рождения. Предоставляют `GetFullName()`, сравниваются по `id` (`operator==`) и печатаются в виде `Фамилия Имя Отчество (id=...)`. Используются как тип элементов дека для демонстрации обобщённости контейнера.

## Интерфейс пользователя

После запуска выбирается тип элементов дека:

```
=== Main Menu (element type) ===
1. SegmentedDeque<int>
2. SegmentedDeque<double>
3. SegmentedDeque<string>
4. SegmentedDeque<char>
5. SegmentedDeque<Student>
6. SegmentedDeque<Teacher>
0. Exit
```

Затем задаётся длина сегмента и стартовый набор элементов, после чего доступно меню операций над деком:

```
=== SegmentedDeque Operations ===
Current: { ... }            # текущее состояние дека по сегментам
1.  Get element by index
2.  Append (push back)
3.  Prepend (push front)
4.  PopFirst (pop front)
5.  PopLast (pop back)
6.  InsertAt
7.  GetSubsequence
8.  Concat with new deque
9.  GetFirst / GetLast
10. GetLength
11. FindSubsequence
0.  Back
```

Ввод проверяется на корректность (повтор при ошибке), а исключения операций (выход за границы, пустой дек и т.п.) перехватываются и выводятся как `Error: ...`.

## Тестирование

Модульные тесты написаны на **GoogleTest** и расположены в `include/collections/tests/`:

| Файл | Что проверяет |
|------|---------------|
| `TestSegmentedDeque.cpp` | Сегментированный дек: push/pop с обоих концов, индексация, `InsertAt`, `GetSubsequence`, `Concat`, `FindSubsequence`, границы |
| `TestStack.cpp` | Стек: `Push`/`Pop`/`Peek`, `Concat`, `Clear`, пустые случаи |
| `TestDoublyLinkedList.cpp` | Двусвязный список: вставки/удаления, обход, границы |
| `TestDynamicArray.cpp` | Динамический массив: доступ, `Resize`, копирование |
| `TestArraySequence.cpp` / `TestListSequence.cpp` / `TestAdaptiveSequence.cpp` | Последовательности из прошлых лаб |
| `TestLinkedList.cpp` / `TestBitSequence.cpp` / `TestMapReduce.cpp` | Список, битовая последовательность, операции Map/Where/Reduce/Zip |
| `TestThrowCases.cpp` | Корректность выброса исключений в граничных случаях |

Точка входа тестов — `tests.cpp` (`RUN_ALL_TESTS`), сборка — таргет `tests` в `Makefile`. Тесты собираются с санитайзерами (`-fsanitize=address,undefined`).

> Примечание: для сборки тестов нужен GoogleTest. Путь к нему задаётся переменной `GTEST_DIR` в `Makefile` (по умолчанию `../googletest/googletest`).
